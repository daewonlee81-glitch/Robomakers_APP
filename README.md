# 로보메이커스 워드블럭 웹 에디터 (v0.3.12)

크롬에서 바로 쓰는 **SPIKE Prime · SPIKE Essential · EV3** 용 워드블럭 코딩 프로그램입니다.
허브에는 **Pybricks 최신 펌웨어(v4)** 가 설치되어 있어야 하며, 블록은 Pybricks 파이썬 코드로 바뀌어 허브에서 실행됩니다.

## 실행 방법 (로컬 웹)

압축을 푼 폴더에서 운영체제에 맞는 파일을 **더블클릭**하면 이 컴퓨터 안에서 웹 서버가 켜지고 크롬이 열립니다.
열린 검은 창(서버)을 닫으면 종료됩니다. 주소는 `http://localhost:8000` (사용 중이면 8001, 8002 …).

| 운영체제 | 실행 파일 | 필요한 것 |
|---|---|---|
| Windows 10/11 | `start-windows.bat` | 없음 (윈도우 기본 PowerShell 사용) |
| macOS | `start-mac.command` | python3 (처음 한 번 `xcode-select --install`). 처음엔 우클릭 → 열기 |
| Linux · 크롬북(Linux) | `start-linux.sh` | python3 |

- Web Bluetooth·WebUSB·카메라는 `localhost` 에서 동작합니다. `index.html` 을 파일로 직접 열면(`file://`) 동작하지 않습니다.
- 블록 코딩·컴파일·허브 연결은 인터넷 없이 됩니다. **AI 카메라**와 글꼴(Pretendard)만 처음에 인터넷(CDN)에서 받습니다.
- 다른 컴퓨터에서 접속하게 하려면 GitHub Pages 등 HTTPS 호스팅에 폴더째 올리세요.

### 사용 순서
1. 위쪽에서 허브 종류 선택 → **허브 연결** (Prime/Essential 은 허브 전원 켜고 블루투스 목록에서 선택, EV3 는 USB 케이블 연결 후 선택)
2. 블록을 「▶ 프로그램 시작할 때」 아래에 붙이기 (떨어진 블록은 실행되지 않음)
3. **▶ 실행** (Ctrl+Enter). 터미널에 `print` 출력과 오류가 보입니다. 컴퓨터 없이 쓰려면 **📥 허브에 다운로드** (저장만) → 허브 버튼으로 실행
4. AI 카메라 / 웹 게임패드는 해당 탭을 켜 두면 **프로그램이 실행 중일 때** 0.08초마다 값을 허브로 보냅니다


### AI 카메라 사물·색 (v0.3.0 추가)

- 카메라 탭 위의 칩(손 / 스켈레톤 / 사물 / 사물 학습 / 색)으로 쓸 기능만 켭니다. 많이 켤수록 느려집니다.
- **사물 학습**: 1~5번 이름을 쓰고 「📸 누르고 있기」를 누른 채 물건을 여러 각도로 비춥니다(번호마다 20장 이상 권장, 최대 100장). 아무것도 없는 배경도 한 번호로 학습하면 더 정확합니다.
- **색 학습**: 물건을 화면 가운데 네모에 대고 「학습」. 같은 색 덩어리를 화면 전체에서 찾아 X·Y(0~100)·크기(%)를 보냅니다.
- 학습 내용은 이 브라우저에 저장되고, 「내보내기」로 `.json` 파일을 만들어 다른 컴퓨터에서 「불러오기」 할 수 있습니다.
- 허브로 보내는 줄: `O:`(사물 3개) `T:`(학습 사물 번호, 확신도) `C:`(가운데 색, RGB) `K:`(학습 색 5개).

### LMS-ESP32 (PUPRemote) 연결 (v0.3.1)

- **⬇ 다운로드 → ESP32 쪽 파일**: 허브 프로그램의 「ESP32 채널/명령 등록」 블록에 맞춘 `main.py` + `lpf2.py`·`pupremote.py`(PUPRemote 2.1.3) 를 zip 으로 받습니다. 포트가 여럿이면 `port_A/`, `port_B/` … 로 나뉩니다.
- **Pybricks 4.x 허브는 ESP32 쪽 lpf2.py 2.1 이상이 필요**합니다 (2026-06 PUPRemote 수정). 옛 펌웨어에 든 lpf2 로는 허브에서 `OSError: [Errno 19] ENODEV` 가 납니다. 복사한 파일이 펌웨어 내장본보다 먼저 쓰이고, ESP32 터미널에 `lpf2 2.1.3` 이 찍힙니다.
- 허브는 ESP32 를 최대 4초 기다린 뒤 오류를 냅니다. ENODEV 가 나면 터미널에 확인 목록(💡)이 나옵니다 (ESP32·BluePad32·허스키렌즈 각각).
- `power=True` 에서 채널/명령 이름은 영문 5글자 이하. 등록 순서·이름·형식은 허브와 ESP32 가 같아야 합니다.

### ESP32 핀 직접 제어 — 서보·네오픽셀 (v0.3.2)

- ESP32 카테고리의 **ESP32 핀** 블록: 디지털 출력/입력(풀업·풀다운), 아날로그 입력(0~4095), PWM(0~100%), 서보(0~180°), 네오픽셀(설정·한 개·모두, 색 목록 또는 RGB).
- ⬇ 다운로드 → 「ESP32 쪽 파일」의 `main.py` 안에 I/O 코드(`esp32/rm_io.py` 내용)가 함께 들어갑니다(v0.3.4 부터, 따로 복사할 파일 없음). I/O 명령 6개(pmode, inp, dout, pwm, servo, npx)가 맨 앞에 등록되고, 직접 만든 채널/명령은 그 뒤에 이어집니다.
- 허브는 ESP32 가 연결될 때까지 최대 8초 기다립니다(명령이 많으면 처음 연결 정보가 길어짐).
- 허브는 프로그램 시작 때 ESP32 핀을 초기화하고, 핀을 처음 쓸 때 모드를 정합니다. 입력 핀은 8개까지. 허브 통신 핀(lms_esp32.RX_PIN/TX_PIN, 보통 18·19)은 막혀 있습니다.
- 서보는 50Hz, 0.5~2.5ms. 서보·밝은 네오픽셀은 별도 전원을 권장합니다.

- **서보 자동 기다리기 (v0.3.7):** 서보 블록은 서보가 움직일 시간만큼(약 0.2초/60°, 그 핀의 첫 움직임은 0.5초) 기다린 뒤 다음 블록으로 넘어갑니다. 「90° → 0°」를 바로 이어 붙여도 움직임이 보입니다. 파이썬에서 기다리지 않으려면 `esp32_D.servo(21, 90, False)`. 시뮬레이터도 같은 시간만큼 기다립니다.

### 허스키렌즈 모니터 (v0.3.3)

- 오른쪽 **허스키렌즈** 탭(SPIKE Prime·Essential): 포트를 고르고 **▶ 모니터 실행** → 허브가 husky_spike_esp32 브리지 값을 읽어 보내고, 320×240 화면에 네모(블록형) 또는 화살표(라인 추적)로 그립니다. ID·X·Y·W 와 SPIKE App 워드 블럭 이름(색상·원시 빨강/초록/파랑)을 함께 보여 줍니다.
- 허스키렌즈 블록을 쓴 내 프로그램을 실행할 때도 탭을 열어 두면 같은 값이 보입니다. 탭이 열려 있을 때만 에디터가 `M:1` 프레임을 보내고, 허브 `rm_husky` 가 0.1초마다 `@HK:포트,ID,v1,v2,v3` 줄을 출력합니다(터미널에는 숨김).
- 브리지는 첫 번째 결과 하나만, 높이 없이 보내므로 네모 높이는 W 로 어림합니다.

### ESP32 에 파일 넣기 — Thonny IDE (v0.3.5 안내 추가)

1. thonny.org 에서 Thonny 설치, ESP32 를 USB 로 연결
2. 오른쪽 아래(도구 → 옵션 → 인터프리터)에서 **MicroPython (ESP32)** + 포트. 셸에 `>>>` 가 보이면 연결됨 (글자가 계속 올라가면 빨간 정지 버튼)
3. 보기 → 파일 → 「이 컴퓨터」에서 `main.py`, `lpf2.py`, `pupremote.py` 선택 → 오른쪽 클릭 **「/에 업로드」**
4. **꼭 다시 시작**: 셸에서 Ctrl+D(소프트 리셋) 또는 리셋 버튼 → 셸에 `lpf2 2.1.3` 확인. 안 하면 옛 프로그램이 돌아 허브에서 `ENODEV` (2026-11-09 실제로 겪음)
5. ESP32 를 허브 포트에 꽂고 2~3초 뒤 ▶ 실행. 크롬북은 ViperIDE(viper-ide.org)로 같은 방법

같은 안내가 사용 방법 팝업 「LMS-ESP32 연결」, zip 안의 README.txt, 생성된 main.py 맨 위 주석에 7개 언어로 들어 있습니다.

### AI 카메라 학습 방법 안내 (v0.3.11)

AI 카메라 탭 아래쪽에 접는 칸 **📖 AI 카메라 학습 방법 안내**가 있습니다 (펼침 상태 기억). 위쪽 도구 줄과 「사물 학습」·「색 학습」 칸 제목 옆의 **📖 학습 방법** 버튼은 칸을 펼치고 그 부분으로 바로 스크롤합니다. 위두 메이커스(wedo-makers) 의 「학습 방법 안내」를 참고해 우리 화면·블록 이름에 맞게 다시 썼습니다.

- 🧠 AI는 어떻게 배울까요 — 특징 숫자 1,024개, 가장 비슷한 학습 사진 5장(최근접 이웃) 그림, 확신도 = 5장 중 같은 종류 비율, 따로 「학습시키기」 버튼 없음
- 📦 사물 학습 5단계 · 🎨 색 학습 4단계 · 잘 배우게 하는 법
- 🔌 로봇에서 쓰려면 (▶ 실행 중 카메라 켜 두기, 브라우저 저장·내보내기/불러오기, 시뮬레이터도 같은 학습 결과)
- 🤖 예제 아이디어 (분류 로봇, 색 따라가기, 확신도 게이지, 예제 메뉴)
- 화면: `js/aiguide.js`, 글: `tools/aiguide_text.py` (7개 언어, 각 언어의 실제 버튼·블록 이름과 맞춤)

### 단계별 배우기 — 라인 트레이싱 · 자이로 주행 (v0.3.8)

오른쪽 **배우기** 탭, 위쪽에서 수업을 고릅니다.

- **라인 트레이싱** (Prime · EV3): **1 온오프 → 2 P 제어 → 3 PD 제어 → 4 PID 제어**
- **자이로 주행** (Prime · Essential): **1 방향(요) 재기 → 2 바퀴만 직진 → 3 자이로 P 직진 → 4 PI 직진(적분 ±200 제한) → 5 사다리꼴 속도(「더 느린 쪽」을 골라 속도 튐 방지) → 6 자이로 돌기(비례 감속 · 판정 ±1° · 0.3초 확인) → 7 Pybricks 자이로(DriveBase use_gyro)**. 시뮬레이터는 「격자」 매트로 열림

- 단계마다 원리 설명 · 그림(조향 그래프 / 오차-시간 그래프) · 이번 단계에서 바뀐 블록 · 해 보기(Kp·Kd·Ki 바꿔 보기)
- 「이 단계 블록 불러오기」 → 작업 공간이 그 단계 프로그램으로 바뀌고 **새로 생긴 블록이 노랗게 빛남** (10초, 「새 블록 보기」로 다시)
- 「🧪 시뮬레이터에서 해 보기」 → 캐드 시뮬레이터가 「라인 트레이싱」 매트로 열림
- 로봇: 바퀴 A·B + 컬러 센서 C (EV3 는 S3), 선의 왼쪽 가장자리, 속도 120 mm/s, 목표값 50, Kp 1.2, Kd 4, Ki 0.02 (적분 ±1000 제한). Prime · EV3 (Essential 은 포트 2개라 안내만)
- 변수 이름은 언어마다 (목표값·오차·조향… / target·error·steer…)
- 프로그램: `js/lessons.js` (블록마다 고정 id → 앞 단계에 없던 블록 = 새 블록), 화면: `js/learn.js`, 글: `tools/learn_text.py` (7개 언어, 실행하면 언어 파일에 씀). 새 수업은 `LESSONS` 에 추가

- 위쪽 **🧪 시뮬레이터** 버튼: 지금 블록과 허브 종류를 들고 [로보메이커스 캐드](https://daewonlee81-glitch.github.io/mindstorms-cad/) 시뮬레이터 화면으로 바로 갑니다 (새 탭 `rm-cad`).
- 시뮬레이터의 **✏️ 워드블럭 에디터로** 버튼: 시뮬레이터에서 고친 블록을 에디터로 다시 가져옵니다.
- 두 사이트가 같은 주소(github.io)라 브라우저 저장소(`rm-wb-handoff`)로 주고받습니다. 사물 학습·색 학습 결과도 같은 저장소를 쓰므로, **학습은 에디터 AI 카메라 탭에서** 하면 시뮬레이터에서도 그대로 씁니다.
- 시뮬레이터에서 새 블록: 사물 인식·사물 학습·색 인식·색 학습은 카메라로 실제 동작, ESP32 핀 블록은 「ESP32 없음」 안내 후 값 0 (실제 허브로 보내면 동작).

**에디터를 고친 뒤 시뮬레이터에도 반영하는 법** — 캐드 저장소를 옆 폴더(`../mindstorms-cad`)에 받아 두고:

```
python3 tools/sync_cad.py      # → ../mindstorms-cad/wordblock-sync.js 를 다시 만듦 (블록 문구 · 허브 라이브러리)
```

새 블록을 시뮬레이터로 더 옮기려면 `tools/cad/wordblock-sync.tpl.js`(블록 정의·생성기·도구 상자)와 `tools/sync_cad.py` 의 `WANT`(가져올 문구)를 고칩니다. 캐드의 `app.js` 는 압축된 빌드 파일이라 훅 네 줄만 들어 있습니다: `window.__wb` 에 내부 함수 노출, `window.__wbKeys`(카메라 기능 켜기), `window.__wbFrames`(실제 허브로 O·T·C·K 값 중계), `window.__wbTb`(도구 상자).

## 업데이트 올리는 법 (GitHub Pages)

GitHub Pages 는 파일을 브라우저에 **10분 동안 캐시**합니다. 그래서 새 파일을 올려도 바로 안 보이거나, 옛 파일과 새 파일이 섞여 화면이 이상해질 수 있습니다.

1. 코드를 고쳤다면 `python3 tools/set_version.py 0.3.12` 처럼 **버전을 올립니다**. 모든 파일 주소 뒤에 `?v=버전` 이 붙어, 브라우저가 새 파일을 바로 받습니다.
2. 폴더 전체를 저장소에 올립니다 (`index.html` 이 저장소 맨 위에 있어야 함).
3. 1~2분 뒤 **강력 새로고침**: Windows·크롬북 `Ctrl + Shift + R`, Mac `Cmd + Shift + R`.

## 설정 바꾸기

- **버그 신고 연락처·버전**: `js/config.js` 의 `contactEmail`, `contactName`, `version` (GitHub 이슈 주소를 `issuesUrl` 에 넣으면 버튼이 생깁니다)

- 사용 방법 팝업은 버전(0.2 등)이 바뀌면 다시 한 번 자동으로 뜹니다. 주소 뒤에 `?nohelp` 를 붙이면 뜨지 않습니다.

## 동작 원리

- **컴파일**: 메인 코드의 `import` 를 따라가 `hublib/` 모듈을 찾아 각각 mpy-cross(ABI 6)로 컴파일하고
  `[크기 u32][이름\0][mpy]` 형식으로 이어 붙입니다 (Pybricks Code 와 같은 방식, 첫 모듈이 `__main__`).
- **다운로드**: Pybricks Profile 명령 `WRITE_USER_PROGRAM_META(0)` → `WRITE_USER_RAM` 조각들 → `META(크기)` → `START_USER_PROGRAM(슬롯 0)`.
  USB 는 같은 명령 앞에 메시지 종류 바이트(0x02)를 붙이고 응답을 기다립니다.
- **웹 → 허브 데이터**: 실행 중인 프로그램의 stdin 으로 한 줄 프레임을 보냅니다.
  `H:감지,제스처,X,Y,손가락` / `P:감지,코X,코Y,왼손,오른손,몸X,기울기,양팔` / `G:LX,LY,RX,RY,LT,RT,버튼비트,방향키`.
  1.5초 동안 새 값이 없으면 허브 쪽은 "끊김"(0)으로 처리합니다.

## 허스키렌즈 펌웨어 권장 수정 (선택)

`husky_spike_esp32/firmware/main.py` 의 mode5 4번째 값에 ID 를 넣으면 Pybricks 에서 모드 전환 없이 한 번에 읽어 더 빠르고 안정적입니다.
SPIKE App 워드블럭(원시 빨강/초록/파랑)에는 영향이 없습니다.

```python
# 284, 290행
lp.mode_values = {0: [oid], 1: [0], 5: [v1, v2, v3, oid]}
lp.load_payload([v1, v2, v3, oid], 5)
```

수정하지 않아도 동작합니다 (이때는 mode0 을 따로 읽어 ID 를 얻습니다).
